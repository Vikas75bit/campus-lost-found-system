# University Lost & Found Intelligence System
**Database Management Systems (DBMS) Mini-Project**

A centralized university campus lost-and-found platform built with **PostgreSQL + pgvector**, **FastAPI**, and **Next.js App Router (TypeScript + Tailwind CSS)**. It enables authenticated campus users to report lost items, supports staff in recording physically received found items, discovers candidate matches via dense semantic embeddings (`all-MiniLM-L6-v2`) + structured metadata, enforces staff-led ownership verification, and atomically records physical handovers with an immutable audit trail.

---

## Architecture & Database Paradigms

1. **PostgreSQL 16/18 (Relational Transactional Store)**:
   - 3NF normalized relational tables (`users`, `categories`, `campus_locations`, `lost_items`, `found_items`, `match_candidates`, `claims`, `handovers`, `notifications`, `audit_logs`, `status_history`, `revoked_tokens`, `password_reset_requests`).
   - Enforces Foreign Keys (`ON DELETE CASCADE` / `RESTRICT`), `UNIQUE`, `NOT NULL`, `CHECK` constraints, PL/pgSQL triggers (`trg_audit_*_status`, `trg_check_claimable_item`), stored procedure (`process_physical_handover`), relational views (`vw_public_found_items`, `vw_staff_match_queue`, etc.), and GIN Full-Text Search indexes.
2. **pgvector (Persistent Vector Store)**:
   - Stores 384-dimensional L2-normalized embeddings generated by `sentence-transformers/all-MiniLM-L6-v2` in `lost_items.embedding` and `found_items.embedding` (`vector(384)`).
   - Uses HNSW cosine indexes (`USING hnsw (embedding vector_cosine_ops)`) and the `<=>` cosine distance operator with SQL metadata filtering (`category_id`, `status`) for persistent semantic retrieval.
   - **Invariant**: Similarity scores are candidate retrieval aids only—matching never establishes ownership, approves claims, or authorizes handovers.

## Technology Stack

| Layer | Technology |
| :--- | :--- |
| **Frontend** | Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS, Lucide React |
| **Backend API** | FastAPI, Pydantic v2, SQLAlchemy 2.0, Uvicorn |
| **Relational + Vector DB** | PostgreSQL + `pgvector` (`vector(384)`, HNSW cosine index, GIN FTS) |
| **Embeddings & Matching** | `sentence-transformers/all-MiniLM-L6-v2` (384-dim), Hybrid Multi-Signal Ranker |
| **Authentication & RBAC** | JWT (HS256, `jti` revocation), Bcrypt hashing, Next.js Middleware + FastAPI RBAC |
| **Testing** | Pytest (26 automated unit, constraint, workflow, and auth tests on PostgreSQL) |

## Quick Start (Local Development)

### Option A: Docker Compose (PostgreSQL + pgvector, FastAPI, Next.js)
```bash
docker compose up --build
```
- Next.js Frontend: `http://localhost:3000`
- FastAPI Backend & Docs: `http://localhost:8000/docs`

### Option B: Local Run (PostgreSQL + pgvector running on `localhost:5432`)
1. **Backend dependencies & API server**:
   ```bash
   pip install -r requirements.txt
   python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
   ```
2. **Frontend dependencies & Next.js server**:
   ```bash
   cd frontend
   npm install
   npm run build
   npm run start
   ```
3. Open **http://localhost:3000** in your browser.

### Automated Tests & Benchmark
```bash
python -m pytest backend/tests -v
python run_evaluation.py
```
